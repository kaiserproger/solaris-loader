# solaris-loader

Standalone Gradle workspace for the Solaris real-client agent and Loader
platform adapters (`bridge-core`, `fabric-agent`, `java-agent`, `loader-core`,
`loader-fabric`, `loader-neoforge`, `loader-forge`, `loader-platform-common`).
Developed independently from the Solaris core repository.

## Layout

- Check out as a sibling of core: `../solaris` (override points below when
  the layout differs).
- Core integration points (no old `client-mod/` fallback):
  - `SOLARIS_REPO_ROOT` env or `-Psolaris.repoRoot` for `loader-core` tests
    (default `../solaris`; resolves `examples/loader-live-gate` fixtures).
  - `SOLARIS_CLIENT_JAR` env or `-Psolaris.clientJar` for `java-agent`
    (default `../solaris/.analysis/client-automation/versions/26.1.2/client.jar`).
  - Core launches this workspace via `SOLARIS_LOADER_ROOT` (default
    `../solaris-loader`); see the core harness docs.
- Local-only caches stay under `.analysis/` (game dirs, client jars) and are
  ignored. Never commit Mojang/mapped/generated bytes.

## Build

Requires Java 25. MCP runs need `SOLARIS_CLIENT_MCP_TOKEN` (and optionally
`SOLARIS_CLIENT_MCP_PORT`, `-Psolaris.clientMcp.gameDir`):

```sh
./gradlew :loader-core:test :loader-fabric:test :loader-neoforge:test :loader-forge:test
./gradlew :loader-fabric:jar :loader-neoforge:jar :loader-forge:jar
SOLARIS_CLIENT_MCP_TOKEN="$(openssl rand -hex 32)" ./gradlew --no-configuration-cache :fabric-agent:runClientMcp
```

Keep the protocol-2 Loader wire format and module APIs unchanged; this repo
owns the bridge/Java/platform modules, not the core harness, CI, or docs.
