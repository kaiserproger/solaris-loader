# krasnokamen-loader

Standalone Gradle workspace for the Krasnokamen real-client agent and Loader
platform adapters (`bridge-core`, `fabric-agent`, `java-agent`, `loader-core`,
`loader-fabric`, `loader-neoforge`, `loader-forge`, `loader-platform-common`).
Developed independently from the Krasnokamen core repository.

This repository (formerly Solaris, renamed Krasnokamen on 2026-11-12) keeps its
checkout directory name `solaris-loader` and the core sibling `../solaris` on
the owner host; Java packages, mod ids, channels and env vars all use
`krasnokamen`.

## Layout

- Check out as a sibling of core: `../solaris` (override points below when
  the layout differs).
- Core integration points (no old `client-mod/` fallback):
  - `KRASNOKAMEN_REPO_ROOT` env or `-Pkrasnokamen.repoRoot` for `loader-core` tests
    (default `../solaris`; resolves `examples/loader-live-gate` fixtures).
  - `KRASNOKAMEN_CLIENT_JAR` env or `-Pkrasnokamen.clientJar` for `java-agent`
    (default `../solaris/.analysis/client-automation/versions/26.1.2/client.jar`).
  - Core launches this workspace via `KRASNOKAMEN_LOADER_ROOT` (default
    `../solaris-loader`); see the core harness docs.
- Local-only caches stay under `.analysis/` (game dirs, client jars) and are
  ignored. Never commit Mojang/mapped/generated bytes.

## Build

Requires Java 25. MCP runs need `KRASNOKAMEN_CLIENT_MCP_TOKEN` (and optionally
`KRASNOKAMEN_CLIENT_MCP_PORT`, `-Pkrasnokamen.clientMcp.gameDir`):

```sh
./gradlew :loader-core:test :loader-fabric:test :loader-neoforge:test :loader-forge:test
./gradlew :loader-fabric:jar :loader-neoforge:jar :loader-forge:jar
KRASNOKAMEN_CLIENT_MCP_TOKEN="$(openssl rand -hex 32)" ./gradlew --no-configuration-cache :fabric-agent:runClientMcp
```

Playable iron-smelting stages read received furnace menu burn/cook data and
fuel slot contents before each smelt, rather than assuming residual burn
survives ore-gathering trips. Chestplate progression collects five initial logs:
20 planks minus table (4), sticks (2), and wooden pickaxe (3) leaves 11 before
furnace placement, sufficient for eight independently fuelled smelts without
a later log trip. Observations record the actual menu values and fuel decision.
Fuel-policy regressions live in `PlayableHeatStageTest`, `PlayableToolStageTest`,
and the strict no-post-furnace-trip case in `PlayableCombatStageTest`.

Keep the Loader wire protocol **3** and client artifact index **schema 2**
contract: `loader-core` owns every codec and validation (protocol 3 handshake
with `views`/`view_actions`/`world_previews`/`world_selection` content kinds,
the schema-2 `screens` index with its eight widget types, overlay
`input_bindings` and `view_request_bindings` (one shared eight-key bound), and
bounded `world_previews`, the `krasnokamen:loader/view` and `krasnokamen:loader/view_action`
wire-3 view messages and the protocol-3 sound channel), the three platform
adapters supply platform identity, native payload registration and lifecycle
only, and `loader-platform-common` owns rendering. Schema-1 indexes and the
removed UI/interaction shapes are deleted rather than bridged; this repo owns
the bridge/Java/platform modules, not the core harness, CI, or docs.
